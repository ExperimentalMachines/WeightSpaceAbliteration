## 4. Off-run preparation

Yes, if it happens in a branch with temporary directories, never touches `runs/`, and passing tests are not called validation.

**Capability tests (stubbed subprocess):**
- argv contains the pinned revision, each seed and the thinking policy;
- the output path is absolute;
- results are discovered fresh per seed, never "lexicographically last";
- empty or missing tasks and metrics fail the gate.

**Judge tests (tiny CPU model):**
- no item is truncated, with truncation side checked explicitly;
- the raw first token is saved, with a census of yes / no / other, and "other" is never silently False;
- batch-1 unpadded verdicts equal batched left-padded verdicts;
- each judge uses its own template.

**Memory:** the caller must drop its own reference, and peak allocation is measured only at GPU validation.

**Construct:** tests cannot fix it. "Not HarmBench-yes" needs a separate refusal measure or the human calibration, and safe-prompt over-refusal needs its own instrument.
