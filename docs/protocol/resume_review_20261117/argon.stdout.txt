### 3. Required Retractions & Qualifications in `EXECUTION_LOG.md`

The following claims in [EXECUTION_LOG.md](../../../EXECUTION_LOG.md) must be explicitly retracted or qualified:
1. **"Parent refuses 81.6% / 79.8% of harmful prompts" ([EXECUTION_LOG.md](../../../EXECUTION_LOG.md#L353-L356)):** Retract as refusal rates. `judge_is_refusal` ([judge_fix.py](../../../harness/judge_fix.py#L121-L129)) computes `not judge_harmbench(...)` (`NOT-HARMBENCH-YES`). HarmBench (`2402.04249`) classifies *unambiguous harmful compliance* (attack success), not refusal. Non-harmful outputs include benign answers, topic deflections, and incoherent text.
2. **"Genuine over-refusal on safe prompts (61.3%) ... property of the model, not the harness" ([EXECUTION_LOG.md](../../../EXECUTION_LOG.md#L358-L367)):** Retract completely. Applying `not judge_harmbench` to safe prompts from XSTest (`2308.01263`) and OR-Bench (`2405.20947`) labels every **safe, helpful compliance** (`No`, not harmful) as `True` ("refusal"). Thus 61.3% (962/1,569) measures *non-harmful responses to safe prompts* (and implies 38.7% were judged harmful), not over-refusal.

5. **"`gates_optimized.py` ready for next run" ([EXECUTION_LOG.md](../../../EXECUTION_LOG.md#L425)):** Retract: it fails `ast.parse` at line 52 and does not free VRAM.
6. **"Controls v2" ([EXECUTION_LOG.md](../../../EXECUTION_LOG.md#L388-L410), [controls_passing.md](../../../docs/protocol/controls_passing.md)):** Must be explicitly labeled a **post-baseline amendment** adopted after observing parent probe AUC (0.9992) and random-direction `q975` (0.9364), not an untouched pre-registration. Per Elazar et al. (`2006.00995`) and Zhao et al. (`2507.11878`), probe changes under source-aliased splits cannot support causal refusal-erasure claims.

### 4. Off-Run Code Preparation, Unit Testing & Technical Assessment

**Yes, we may prepare and unit-test code off-run (on CPU/synthetic fixtures) while scientific execution is held**, provided no gates are executed against `runs/` and any eventual adoption in a run is preceded by owner approval and a recorded deviation.

**Technical Assessment of Code Bugs & Construct Concerns:**
- **`harness/gates_optimized.py`:**
  - *Verifiable bug:* Line 52 (`from harness.gates import ..., LLAMA2_CLS_PROMPT if ... else None`) is a `SyntaxError` in Python (`ast.parse` fails).
  - *Verifiable bug:* `_free_model(model)` ([gates_optimized.py](../../../harness/gates_optimized.py#L31-L40)) executes `del model` on the local parameter binding while the caller scope (`check_refusal_eval_sequential` lines 89, 123; `check_over_refusal_eval_sequential` lines 156, 170) retains `model` / `judge` references, keeping weights pinned in VRAM during Phase 2.
- **`harness/judge_fix.py` & Construct Validity:**
  - *Construct error:* HarmBench classifiers test harmful compliance (`Yes` = harmful). Inverting `Yes` (`not harmful`) conflates refusal with safe helpful answers (breaking `over_refusal_eval` completely) and with incoherent/irrelevant completions on harmful prompts. Safe-prompt over-refusal requires a dedicated refusal judge or lexical/calibrated refusal detector (per XSTest `2308.01263` / OR-Bench `2405.20947`), and copyright items require their separate hash/overlap route.
  - *Template & Logit equivalence:* `judge_fix.py` applies `LLAMA2_CLS_PROMPT` (`[INST] <<SYS>>...`) to both `cais/HarmBench-Llama-2-13b-cls` and `cais/HarmBench-Mistral-7b-val-cls` (`judge_alt` in [harness.json](../../../runs/20261110T135200Z-weightspace-abliteration-qwen3.5-0.8b/harness.json#L22-L25)), which uses a different chat/system prompt format. Also, left-padded batched forward passes (`out.logits[:, -1, :]`) without explicit `position_ids` handling or verification against single-item unpadded `.generate(max_new_tokens=1)` can suffer from padding-induced logit drift in bfloat16.
- **`check_capability_suite` ([harness/gates.py](../../../harness/gates.py#L725-L748)):**
  - *Verifiable bugs:* (1) Omits `revision={cfg['model']['revision']}` in `--model_args`; (2) ignores `cfg["seeds"]["capability"]` (`[0, 1, 2]`); (3) passes `--apply_chat_template` without pinning `enable_thinking=False` policy; (4) runs with `cwd=str(run_dir)` while passing relative `out_dir = run_dir / "results" / "lm_eval"`, creating nested `runs/<id>/runs/<id>/results/lm_eval` paths; (5) globs `sorted(out_dir.glob("**/results*.json"))[-1]`, which can silently pick stale JSONs from prior runs or return `{}` with `"passed": True` if empty (violating `gate-non-vacuity`).
- **`modal_runner.py` Synchronization:**
  - `upload_repo` uses `batch_upload(force=True)`, overwriting remote files without deleting stale volume artifacts (such as older `.omp` files), and `pull_results` overwrites without a pre-write hash check local `runs/` files with `write_bytes()`. `pull_results` needs a pre-write hash check that refuses to overwrite any existing receipt/log with differing bytes.

**Minimal CPU Unit Tests Required Before Any GPU Validation:**
1. AST/import test across all `harness/*.py` modules and caller-side weakref test proving GPU tensors are unreachable (`gc.collect()`) before Phase 2 loads.
2. Subprocess mock test for `check_capability_suite` verifying exact CLI args (`revision`, per-seed invocation `[0,1,2]`, path resolution under `cwd`, and failure on empty/missing task metrics).
3. Synthetic activation test for the v2 label-constant controls (5-fold salted item-ID CV for Topic and Source controls in `probe_report`).
4. Batched vs. unpadded batch-1 forward equivalence test on a tiny CPU model verifying identical token argmax and `position_ids` alignment.
